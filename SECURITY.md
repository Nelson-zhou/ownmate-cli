# Security

Report vulnerabilities through this repository's private vulnerability reporting. Never include tokens, pairing secrets, encryption keys, personal records, or decrypted reminders in public issues.

The phone approves three independent choices: reminder read, reminder write, and notebook read (journals plus fragments). Write does not imply read. Existing grants do not gain scopes or actions on refresh. Reminder write accepts only CREATE and UPDATE of plan fields; it cannot complete, delete, restore, transfer ownership, modify Document, or access ordinary account/sync writes.

Authorized ciphertext is decrypted locally. Output projection is not cryptographic field isolation: a custom client with the DEK and original journal or fragment ciphertext may decode Context such as location or weather. Grant access only to trusted software. No MEK or ordinary account credentials are granted.

The selected computer, MCP Host, AI service and plugins may retain, copy, synchronize or transmit plaintext that they receive. Their retention, access and training practices depend on their policies, settings and implementation; OwnMate does not claim that every third party trains on this data or that none do. Choosing a trusted client is the user's authorization choice, not an OwnMate certification of that client's security. OwnMate cannot control copies already received by another party or promise that party's future behavior. This risk notice does not waive mandatory responsibilities or commitments of OwnMate or a third party. Review the recipient and grant only the scopes needed before approving the pairing.

Temporary sessions last at most 30 minutes and keep credentials and retry ciphertext only in memory. Trusted credentials use the operating system credential store. Persistent retry caches contain only encrypted command envelopes, never content plaintext, plaintext hashes, DEK, or tokens. They use private Unix permissions or a checked current-user Windows ACL and fail closed if private storage cannot be established.

Pairing control files contain only private nonsecret run/generation/state/expiry metadata and replacement requests. Only the live owner holds its P-256 private key and pairing secret. Replacement requires confirmation of the original pending cancellation or expiry; an approval-winning race completes the original grant without revoking it. Owner loss before verified native storage requires a new pairing, not ordinary-file secret recovery. Local status and owner locks are not proof of current server authorization or credential-store availability.

Linux uses native kernel keyutils as a cache and Secret Service for storage beyond reboot. Trusted use requires a usable user D-Bus session, Secret Service and permitted kernel keyring operations, in addition to the system libdbus runtime. Installing libdbus does not establish a trusted grant. If the executable can run but credential preflight fails, a new pairing offers only phone-approved temporary use; missing runtime libraries or an incompatible loader/ABI prevent temporary use too. Install assistants must follow [AGENTS.md](AGENTS.md): use official package managers only for missing dependencies, never silently elevate privileges, retain login passwords, upgrade the whole system or weaken credential protection. Installing a runtime does not authorize reading existing credentials or records.

Commands are encrypted and have a fixed maximum 24-hour lifetime, further bounded by temporary grant expiry. Retries reuse the exact envelope. The approved phone applies them while the App is in the foreground; queued does not mean saved. Write-only receipts disclose only that grant's request stage and result version, not existing content or the current conflicting version.

Revocation prevents future access and new execution permits. A command already holding a short valid execution permit may complete; applied facts are not automatically rolled back. Revocation cannot erase copies already made by an external application. `disconnect` removes this computer's credentials; revoke the grant in the App to stop subsequent cloud access.

CLI release binaries are unsigned preview builds. SHA-256 files verify integrity, not publisher signatures. Automated Linux/macOS/Windows checks do not prove real credential-store behavior, protection in every Windows ACL environment, complete IANA timezone support, phone pairing, offline application, production database races, or notification delivery. Linux credential-store regressions use synthetic mocks, not a real Secret Service lifecycle. The reminder write production switch and compatible App are required independently of source availability.
